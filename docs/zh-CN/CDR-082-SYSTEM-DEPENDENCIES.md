# CDR-082：XNA系统依赖只读检查

2026-10-03，Primary。待验收、未上传。

后续缓存出口分类将工具检查增至9组；下文8组为本次系统检查阶段记录，没有再次读取系统依赖。最新见[初始化审查](CDR-082-XNA-AUDIT.md)。

## 它在项目中的作用

区分两类问题：“运行零件没找到”和“零件加载时会做什么还不清楚”。这次找齐了限定范围内的零件，但不是角色运行更新，也不能证明原版输入测试安全。

## 完成了什么，是否符合预期

只读检查了8个托管库和4个32位原生库的固定位置，12项均找到，读取前后哈希一致。没有复制、加载或执行这些库，没有下载、安装或访问游戏目录。

VisualC为10.0.0.0，XNA GamerServices/Touch及其余框架库为4.0.0.0，观察到的名称、版本和签名标识匹配对应槽位。8个托管库都没有模块初始化入口；但GamerServices、窗口、绘图和基础框架库仍声明原生调用。这些数量不是本次实际调用次数，也不表示窗口已启动。

4个原生库（msvcr100、xinput1_3、kernel32、user32）都是32位，均有原生入口；kernel32/user32还声明延迟导入。没有TLS声明或模块初始化入口，仍不能排除类型初始化、原生入口、动态加载和间接调用的副作用。托管库文件头标I386也不能单凭这一项判断它只能运行于32位。

下一级依赖只记录名称，不读取、不递归解析；不把这些声明说成“文件缺失”或“运行失败”。原版输入/时间测试仍未执行，没有创建角色。

结论：找齐限定依赖符合预期；“可安全加载”尚未证明。

## 具体验收方式

双击“检查XNA系统依赖.cmd”：应看到12行 SYSTEM_DEPENDENCY，status=inspected，最后为 SYSTEM_DEPENDENCY_AUDIT_COMPLETED targetExecuted=false runtimeSafetyEstablished=false。退出0仅代表只读检查完成。

双击“验证当前版本.cmd”：只跑自有合成检查与保留回归，不读取系统或游戏文件；审查工具现有8项检查，其中包含普通/延迟导入表和负例。摘要留在 artifacts/cdr-082-system-dependencies/summary.json，不含DLL、源码或商业字节。
