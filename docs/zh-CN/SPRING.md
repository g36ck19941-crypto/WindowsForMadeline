# CDR-042 Spring（弹簧）验收说明

> 英文规范：`docs/SPRING.md`。如有差异，以英文版为准。

## 它在项目里有什么用

这一项加入了弹簧。简单说，Player、Theo 或 Glider 碰到弹簧后，弹簧会明确记录“是谁碰到了我”，再只给这个目标一个方向速度。目标控制器会在同一个离线固定时间点真正应用这个速度，而不是只生成一条看起来成功的日志。

弹簧还拥有自己的动作过程：待命、被压下、冷却、重新弹起。目标一直压在上面时不会每一帧重复触发，必须先离开再接触。每个弹簧独立计时，一个弹簧损坏或停用不会改写其他弹簧、Player、Theo 或 Glider。

这为后续 Refill、Water 等实体提供了一个通用例子：实体只输出带目标身份的不可变效果，目标自己负责应用，未来 App 只做安全转交。

## 这次实际完成了什么

- 向上、向右、向下、向左四个确定性方向；只替换发射轴，保留另一轴速度。
- `Ready`、`Retracted`、`Cooldown`、`Disabled` 四种状态。
- 带目标 ID、目标类型、位置、进入速度和是否允许触发的接触快照。
- 带目标身份的通用速度效果，避免把 Spring 直接耦合到 Player、Theo 或 Glider。
- 固定 60 Hz 的压缩、冷却、复位和“离开后才能再次触发”。
- Player、Theo、Glider 实际应用测试，以及双 Spring 隔离和确定性重放。

## 怎样验收

1. 双击项目根目录的 `演示当前进度.cmd`。
2. 打开生成的 `artifacts\cdr-042-demo\index.html`，找到 CDR-042 Spring 表格。
3. 应看到 30 个固定时间点、3 次激活、3 次发射、3 次复位；Player、Theo、Glider 各实际应用 1 次，三者速度在对应行发生变化，并标记重复运行一致。
4. 再双击 `验证当前版本.cmd`。
5. 应看到构建 0 警告、0 错误，Spring `42/42`，总计 `489/489`，最后出现 `CDR-042 OFFLINE VERIFICATION PASSED`。

## 这证明了什么

它证明弹簧的状态过程、目标识别和发射效果能在项目自己的离线物理世界中稳定运行；Player、Theo、Glider 确实接收了速度，而不是只有 Spring 自己报告成功。

## 仍未证明什么

- 原版商业发行版的完整接触判定、压缩时间和速度数值没有公开、充分的事实依据，因此当前行为仍标为 `partial`。
- 正式 App 还没有持续负责 Spring 到各目标的效果路由。
- 没有连接原版 Spring 动画像素，也没有显示到真实桌面。
- 没有读取游戏安装、实时输入，或打开游戏和 GUI。
