# CDR-082 本次更新：旧框架受限启动检查

2026-10-05，Primary。基线1935cc3，分支codex/cdr-082-local-compile-probe。本轮待验收，结论是部分完成。

## 它在项目中的作用

更新的是“启动环境检查”模块，不是角色、动作或素材。

新增一个我们自己写的32位旧框架小程序。它不包含游戏逻辑，目的是在接入原版之前，先检查更接近原版所需框架的启动路线。这样以后遇到“角色还没生成，程序就退出”，可以先区分环境问题与角色、素材问题。

它沿用原有窗口调用限制、资源上限和退出清理，没有为了启动成功而放宽限制，也没有替换此前.NET8的失败记录。

## 实现了什么进度，是否符合预期

- 自有程序编译成功；静态检查确认32位、旧框架目标、一个基础库引用、没有嵌入素材、三项已限定的系统查询声明。父程序编译零警告、零错误。这不是完整运行依赖检查。
- “启动前中止”通过。正常启动在发出“已就绪”通知前退出，后面四项没有运行，不能算通过。
- 在同一限制下复核仍返回2。观察到的自有进程均已退出，Job中剩余进程数为零。
- 实际进程退出码8007045A；最后捕获的调试事件码4000001F。这是两条不同记录，不能把最后一条事件直接当成原因，也不知道哪个组件导致退出。没有第一条文件记录，不等于可以证明程序入口从未执行。

原本预期六项启动/控制检查全部通过；实际只通过一项。因此启动成功的目标未达到。本轮交付了编译、核对、独立验证入口和失败结果展示；原版、XNA和角色没有运行。

资源上限已查询核对，未做压力测试。完整文件、网络、输入、音频和设备隔离仍未证明。旧框架自有程序通过也不能代替原版兼容证明。

## 具体验收方式

双击根目录“验证旧框架受限启动.cmd”。它会先说明用途，再编译和检查自有程序。当前预期看到：

`OWN_FRAMEWORK_SUMMARY status=partial-own-net472-blocked passed=1 failedScenario=Complete`

返回码2代表启动未通过，不是“已经成功但显示异常”。若与你看到的不同，请提供这行以及framework-cases.json中自有程序的最后阶段、退出码和清理结果，不要提供游戏文件或内存转储。

“演示当前进度.cmd”顶部只介绍本轮更新，并展示已有摘要；不会由页面重新执行启动检查。它不是角色画面演示。本轮代理只生成页面，没有打开GUI。
