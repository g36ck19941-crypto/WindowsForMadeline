# CDR-082：XNA缓存与静态审查

2026-10-03，Primary。待验收、未上传。

## 它在项目中的作用

把已确认的运行零件放进本地忽略缓存，并检查它们是否会带来未审查的原生初始化。不能只看“库已经有了”，就直接运行原版测试。

## 完成了什么，是否符合预期

3个系统XNA库已按授权只读复制，原文件和副本哈希一致，版本/身份匹配。没有复制或读取其它新依赖，不访问游戏安装或素材。

静态检查的结果：

| 库 | 纯托管IL | 模块初始化 | 原生方法数 | 原生导入方法数 |
| --- | --- | --- | --- | --- |
| Framework | 否 | 有 | 102 | 122 |
| Game | 是 | 无 | 0 | 11 |
| Graphics | 否 | 有 | 36 | 39 |

发现的依赖名称包含MSVCR100、xinput1_3、user32、Microsoft.VisualC，以及Game引用的窗口、GamerServices和触控组件。

这些声明不等于本次输入测试一定会调用它们，但两个库存在混合原生代码和模块初始化，不能假设“只操作输入数据就一定没副作用”。缓存准备符合预期，运行安全审查尚未完成。

**按你要求遇到依赖或副作用疑点先停止：原版测试没有执行，没有加载目标库、调用原生/真实输入、Steam或音频，也没有角色创建。**

## 具体验收方式

双击“审查缓存XNA依赖.cmd”。会看到3行模块/方法数量和最后 `XNA_STATIC_AUDIT_COMPLETED runtimeSafetyEstablished=false originalTestExecuted=false`。退出0只代表静态审查结束，两个false是当前事实，不是程序错误。

“验证当前版本.cmd”保留此前回归，并增加3项自有元数据工具检查，不读取XNA缓存或系统文件、不运行原版。DLL与详细元数据都留在Git忽略目录，不上传；本次没有角色演示。

## 下一步需要确认

是否允许继续**只读检查相关系统依赖及原生模块初始化链**，仍不执行目标代码？确认后才进一步收敛是否可安全运行已授权的输入小测试。不默许复制新依赖、安装下载、启用原生设备或启动游戏。

当前待确认的是新的静态依赖审查范围，不是重复申请已经批准的“复制3个库”或“原版输入测试”。
