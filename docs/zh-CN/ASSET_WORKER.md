# AssetWorker 协议与监管（中文镜像）

> 英文规范：`docs/ASSET_WORKER.md`。如有差异，以英文版为准。

## 本次新增功能

CDR-011 新增一个真正独立的控制台 Worker 进程和客户端监管器。Worker 目前没有解析器，也没有任何文件系统请求消息。完整协议只有：

- `Hello` → `Ready`
- `Ping` → `Pong`
- `Shutdown` → `Stopped`
- 受限制的 `Error`

## 有界协议

- 协议版本：`1`；
- 帧格式：4 字节小端有效载荷长度，后接 UTF-8 JSON；
- 最大有效载荷：4 KiB，在分配内存前检查；
- 错误码最长 128 个字符；
- 请求 ID 必须非空；
- 拒绝未知字段、未知消息、错误版本、错误 Error 形状、截断帧和非法 JSON。

协议中不存在任意载荷、路径、图片、素材或可执行行为。

## 它在项目中的作用

CDR-011 相当于先为以后的素材解析器准备一个“隔离工作间”。以后解析器碰到损坏或异常数据时，主桌面程序可以关闭出问题的 Worker，再启动一个新的，而不是跟着一起崩溃。因此，它是开始实现第一个 `.meta` 解析器之前必须具备的安全外壳。

它目前还不会读取或理解任何游戏素材，也不能证明 Madeline 已经能够显示或移动。

## 启动边界

框架依赖启动器只接受：

- 名称为 `dotnet` 或 `dotnet.exe` 的宿主；
- 完整绝对路径、确实存在、不是目录、不是重解析点，且名称准确为 `CelesteDesktop.AssetWorker.Process.dll` 的 Worker。

该合同不能被配置为启动 Celeste、Everest 或其他任意程序。Worker 使用 `UseShellExecute=false`、重定向二进制标准输入/输出和 `CreateNoWindow=true`。

## 监管行为

监管器会串行执行生命周期操作，并分别限制启动、请求和关闭时间。预期故障返回 `AssetWorkerOperationResult`，其中包含：

- 稳定操作码；
- 当前状态；
- 受限细节码；
- 实际观察到的进程退出码；
- 恢复动作。

启动、Ping 或关闭失败时，会在有界清理时间内终止并释放会话。会话崩溃或协议被拒绝后进入 `Faulted`，再次执行 `StartAsync` 会创建全新会话。调用方取消和超时会分别报告。

Worker 的兜底异常只向 stderr 写一行受限 JSON，包含时间、运行 ID、事件 ID、子系统、阶段、结果、错误码、异常类型和是否可恢复。二进制协议只写入 stdout。

## 具体验收方式

在仓库根目录运行：

```powershell
.\tools\Verify-CDR011.ps1
```

预期结果：

- Release 构建：0 警告、0 错误；
- CDR-010 回归：`RESULT total=15 passed=15 failed=0`；
- CDR-011：`RESULT total=27 passed=27 failed=0`。

CDR-011 测试覆盖非法/超限帧、错误版本、任意程序启动拒绝、启动/请求/关闭超时、取消、启动期与运行期崩溃、有界清理、新会话恢复，以及真实隐藏 Worker 的 Start→Ping→Stop 生命周期。

## 当前局限

当前没有任何素材请求。CDR-011 通过只能证明进程隔离和生命周期通信受限，不能证明已读取安装、解析 `.meta`/`.data`、读取精灵元数据、获得原版素材或显示画面。

## 验收后开始的功能

验收 CDR-011 后只开始 CDR-012：使用纯合成字节实现独立、有界的 `.meta` 解析器。真实安装访问仍要等到 CDR-016 单独授权。
