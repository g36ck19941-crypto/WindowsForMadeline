# CDR-013 — 有界 Atlas 图页解码器

日期：2026-09-21

## 新增功能

- `AtlasDataDecoder` 把一个可读字节流解码成不可修改的 BGRA32 像素帧。
- 它读取小端宽度、高度、严格为 `0` 或 `1` 的 alpha 标志，以及按字节长度记录的像素游程。
- 带 alpha 的游程包含 alpha；alpha 为零时不再包含颜色。可见游程按蓝、绿、红顺序存储颜色。
- 解码器原样保留通道字节，不调色，也不进行预乘或反预乘变换。
- 输入字节数、尺寸和解码后字节数分别受限。
- 零长度、越界、截断和尾随数据使用稳定的 `ATLAS_DATA_*` 错误拒绝。
- 输出帧自己持有像素副本，并提供小写 SHA-256 指纹；日志不包含原始像素。
- 累计进度演示会生成 1 张合成 Atlas 图页和 2 个命名区域，实际运行 CDR-012 与 CDR-013，逐字节核对 48 个像素，并输出离线 HTML 报告与机器可读安全清单。
- 根目录双击入口让开发者无需手动输入 PowerShell 命令即可演示和验证。

## 格式依据与可信度

公开 Monocle 引擎镜像确认 Packer 元数据会把每个页面名解析到 `.data` 字节流，但该旧镜像把图像交给图形框架，没有公开 Celeste 分支的游程解码细节。因此，本任务根据次级格式观察，独立设计并实现了一个有界的合成格式合同；现在还不能宣称已兼容真实安装。

CDR-016 仍需另行授权，才会对用户明确选择的正版安装做只读一致性验证。如果格式不符，应修改合同和解码器，不能用静默 fallback 掩盖。

## 它在项目中的作用

简单说，它把“压缩的整张素材页说明”还原成内存里的像素。CDR-012 告诉后续代码某张小图在哪里，CDR-013 提供那张大图页的像素，之后才能裁出角色或物品帧。它还没有解析动画、裁出精灵、显示角色，也没有证明真实游戏文件一定兼容。

## 累计项目进度演示

双击根目录的 `演示当前进度.cmd`。它会：

1. 生成一张 8×6 的程序化诊断 Atlas；
2. 把生成的 `.meta` 字节交给 CDR-012；
3. 把生成的 `.data` 游程交给 CDR-013；
4. 逐字节核对解码结果；
5. 生成 `artifacts/cdr-013-demo/index.html` 和 `manifest.json`；
6. 因为是开发者主动双击，再打开本地报告。

报告会直观显示像素图页、两个目录区域、帧指纹、已经连接的阶段以及尚未完成的部分。这是“项目目前能做什么”的演示，不替代自动化测试。

## 安全边界

- 公开解码接口只接收 `Stream`，不能自行选择或枚举文件。
- 测试只使用程序生成的字节。
- 不读取游戏安装或商业图片。代理验证不打开 GUI；开发者双击演示入口时会打开本地报告。
- 只有程序生成的诊断像素颜色写入被 Git 忽略的 HTML 报告；不保存商业像素。

## 具体验收方式

开发者验收时依次双击：

1. `演示当前进度.cmd`
2. `验证当前版本.cmd`

第一个入口预期打开本地报告，其中应显示：

- CDR-012 解析 1 页、2 个条目；
- CDR-013 解码 8×6、共 48 个像素；
- 解码像素与生成源逐字节一致；
- 商业素材字节为 0；
- 明确写出尚未解析动画、显示角色或验证真实安装。

第二个入口预期完成 Release 构建和全部回归，并显示 `VERIFICATION PASSED`（验证通过）。两个入口需要本机具备可构建 .NET 8 项目的 SDK；启动器使用英文控制台提示以避免传统 Windows 命令行编码问题，报告内容为中文。代理与 CI 使用的内部等价命令仍是：

```powershell
.\tools\Verify-CDR013.ps1
```

预期 Release 结果：

- 构建 0 警告、0 错误；
- CDR-010：15/15；
- CDR-011：27/27；
- CDR-012：35/35；
- CDR-013：31/31。
- 累计演示：1 页、2 个条目、48 个精确像素、0 商业素材字节。

还可以人工查看本文件和 `src/CelesteDesktop.AssetWorker.Data/`，确认公开解码方法只接收字节流，没有文件路径 API。

## 验收后开始的功能

验收 CDR-013 后，只开始 CDR-014 的合成 `Sprites.xml` 解析器：读取动画名、帧引用、原点等定义。验收不授权读取真实安装、启动游戏或 GUI、渲染角色、保存商业素材。
