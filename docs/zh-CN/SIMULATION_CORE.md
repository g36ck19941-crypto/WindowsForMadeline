# CDR-020 确定性模拟核心

## 实现内容

`CelesteDesktop.Simulation.Core` 只能通过显式的固定步推进，每秒 60 tick。它不依赖时钟、文件、素材、GUI、操作系统或实时输入。位置和碰撞框使用整像素；小数位移先进入十进制亚像素余量，再稳定地产生整像素移动。精确为 `+0.5` 或 `-0.5` 的中点余量使用稳定的“取偶”规则，因此后续零位移不会让位置来回抖动。

Actor 只和按注册顺序排列的 Solid 碰撞。每次整像素位移逐像素检查，最先注册且相交的 Solid 是阻挡者。Actor 之间在本核心中不互相阻挡。

移动 Solid 会先记录站在上面的 Actor，再移动自身，然后按 Actor 注册顺序处理：发生重叠就推开，原本的乘员就携带。移动会生成每秒单位的 `LiftSpeed`；如果推挤或携带被别的 Solid 卡住，会明确产生 squish 事件，不会静默穿透。

## 具体验收方式

1. 双击 `演示当前进度.cmd`，查看 CDR-020 的 13 行逐 tick 表格。
2. 确认重复运行标记为“完全一致”，表中能看到 `ActorCarried` 和 `ActorBlocked`。
3. 双击 `验证当前版本.cmd`。前七组是资源基础回归，最后一组应为 `28/28`；随后累计演示清单核验通过。
4. 全过程不会读取正版安装，不会启动游戏、GUI 或真实桌面，也不使用实时输入。

## 它在项目中的作用

简单说，这一步搭好了“所有角色和物品共同踩的物理地板”：以后 Madeline、Theo、水母等都能复用同一套亚像素移动、碰撞顺序和移动平台规则，问题也更容易隔离。

但它还没有实现 Madeline 的跑、跳、冲刺、攀爬和体力参数，也不能证明已经还原原版手感。它更没有负责显示角色或桌面交互。

## 验收后开始的功能

CDR-021：在本核心上实现 Madeline Normal/Jump，包括跑动、摩擦、重力、快速下落、土狼时间、跳跃缓冲和可变跳跃，并为每项行为提供逐 tick 证据。CDR-020 未经验收前不会上传。
