# CDR-081 验收：认清原版来源和依赖

状态：离线验证通过，等待你的验收；本次未上传。

## 这次做了什么

新增“只看文件身份、不运行游戏代码”的检查器。它对比当前版本与原版备份候选，核对版本、哈希和需要的外部组件；进度页面现在会解释检查结果，而不是只列测试编号。

CDR-080 已按你的验收上传至独立分支 codex/cdr-080-original-recomposition，提交 f804168；main 未改变。CDR-081 仍只在本地。

## 它在项目中的作用

先确认拿到的是原版还是被 Mod 修改过的版本，避免用错代码重组。还要先找出缺少哪些零件，不能等拼到最后才发现根本不是同一套引擎。

实际发现：
- 当前 Celeste.dll 是带 Mod 标记的 .NET 8 版本，与以前的反编译缓存来源一致。
- orig/Celeste.exe 未检测到所检查的 Mod 标记，是 .NET Framework 4.5 的原版候选；但没有官方纯净哈希认证，不能保证完全未修改。
- 角色、碰撞核、场景、状态机和目标实体类型都在。Actor 实际位于 Celeste 命名空间，不是 Monocle.Actor。
- 原版候选引用三个 XNA 程序集，本次仅在安装根目录和 orig 中查找，没有找到；这不代表整台电脑没安装 XNA。也不能直接把现有 FNA 当成已经兼容的替代品。

## 具体验收方式

1. 双击“演示当前进度.cmd”，应看到原版/Mod 来源说明和明确的“尚无可运行角色”，不是角色动画。
2. 双击“验证当前版本.cmd”，最后应显示 CDR081_VERIFIED suites=13 passed=333 junctionChecks=2 reportChecks=3。它不读取安装目录。
3. 如需重复真实检查，双击“检查原版来源与依赖.cmd”，输入此前指定的正版安装目录，再查看进度页面。空输入会取消；失败请提供阶段、错误码和脱敏异常详情。这个入口不反编译、不运行程序集，也不打开 GUI。

## 仍未证明什么

原版候选是否完全纯净、外部引擎是否兼容、恢复的代码能否编译和运行、角色是否可见可动，都尚未建立。程序集版本 1.0.0.0 不是已经确认的游戏显示版本。
