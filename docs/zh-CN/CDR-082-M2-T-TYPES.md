# M2-T：核对原版需要的数据接口

2026-10-06。本次是只读检查和进度说明更新，不是角色功能更新。

## 它在项目中的作用

接入原版代码前，先弄清它需要接收什么数据。就像连接两台设备前先核对接口，不能因为插头名字相似就直接接上。

这次查看了已经缓存的3个XNA库中的类型说明，并对照我们现有的输入、时间和图像接口。没有运行这些库，也没有读取游戏安装。

## 最近完成了什么

所选22个类型全部找到，缓存哈希与既有记录一致。但“找到了”不等于“已经能用”。明确了三个缺口：

- 输入：现有接口只有移动方向和几个动作，不能完整表达原版需要的按键历史、手柄摇杆、扳机和连接状态。
- 时间：现有接口还没有区分原版所用的两类时间，不能直接当成原版时间接口。
- 坐标和颜色：现有素材坐标和图像接口有自己的用途，不能直接代替原版数值运算或颜色存储。

应用场景：下一步设计适配时，知道哪些数据必须补齐，哪些转换必须核对，避免“能编译，却丢了原版输入细节或产生不同运动结果”。这次没有编写新的玩法来凑接口。

## 是否符合预期

接口清单与对比已完成。原版类型的内部计算规则、自动初始化是否安全，以及现代环境兼容性仍未证明；原版角色还没有生成。

缓存中有两份库包含混合原生代码，也有自动初始化声明。这说明仍需要审查，不能直接接入；不表示本次执行了初始化或调用了设备。没有用旧框架辅助进程承载功能，也没有自行选择替代库。

## 具体验收方式

1. 双击“检查迁移类型接口.cmd”。预期看到 TYPE_CONTRACTS_COMPLETED：assemblies=3、requestedTypes=22、foundTypes=22、missingTypes=0、hashesStable=true、targetAssemblyLoaded=false，退出码0。
2. 双击“演示当前进度.cmd”，看顶部概览和“最近一次更新：核对原版需要的数据接口”。这是说明页面，不是角色画面。代理没有打开GUI。
3. 失败时提供 TYPE_CONTRACTS_FAILED 或 XNA_PREFLIGHT_FAILED 最后一段，不要发送商业明细。

技术证据：8项自有元数据检查、2项范围拒绝、14项摘要展示检查；M1摘要10项、M2摘要11项保留检查重跑。自有最终构建0警告/0错误。早期展示脚本有编码解析失败，后改用ASCII标记；一次构建与尚未结束的展示检查重叠造成文件锁失败，等待结束后串行重做。失败记录不算通过，也不是原版运行失败。完整门禁会运行探针，本轮未运行。
