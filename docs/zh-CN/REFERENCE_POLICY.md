# 参考来源与实现来源政策（中文镜像）

> 英文规范：`docs/REFERENCE_POLICY.md`。如有差异，以英文版为准。

## 参考优先级

1. Celeste 官方公开仓库中确实公开并适用其许可的源码。
2. 用户自有正版安装中的只读事实，只能转化为行为合同或不含商业数据的摘要。
3. 经批准验证工具产生的确定性或差分证据。
4. 外部粉丝项目只能作为可行性和边缘情况的次要参考。

## 独立实现规则

- 实现前先写简短的格式或行为规格。
- 依据规格，在本仓库自己的类型和模块边界内重新实现。
- 不得同时打开外部实现并逐行翻译。
- 不得复制 `desk-madeline` 或其他粉丝项目的大段注释、标识符、类结构、测试或控制流。
- 每个精确结论都要记录来源和可信度。
- 如果来源互相冲突，在解决前必须把能力标记为 `unknown`。

`solstice23/desk-madeline` 可以证明直接读取 Atlas 和使用 DirectComposition 呈现是可行的，但它不是本项目的代码基础、架构负责人或还原准确性的唯一依据。

CDR-012 使用 Crunch 的公开二进制格式说明确认打包器字段含义，只用 desk-madeline 次要核对 `.meta` 头部和文件内裁剪偏移的解释。本项目的读取器、合同、预算、验证流程和测试均独立设计。真实安装一致性在 CDR-016 前仍为未知。

CDR-013 使用公开 Monocle 镜像确认 Packer 会把页面名解析为 `.data` 字节流；该旧镜像没有公开 Celeste 分支的游程解码器，因此游程布局仅根据次级格式观察记录为本地合成合同。本项目独立设计了解码器类型、预算、验证顺序、不可变输出和测试，没有复制外部实现。真实安装一致性在 CDR-016 前仍为未知。

CDR-040 所参考的 Celeste 官方公开仓库没有提供 Theo Crystal 实体实现，因此本项目使用独立设计的固定 tick 基线和已经验证的 Actor/Solid 合同。程序生成的 Player/Solid/实体交互测试只证明确定性和故障隔离，不能证明原版数值一致；在获得更强证据并单独记录前，行为保持 `partial`。

CDR-041 所参考的官方公开仓库同样没有发布商业版 Glider 实体实现。拿起、携带者缓降效果、飞行和碰撞参数均基于已验证本地合同独立设计。程序生成的 Player/Solid/Theo/双 Glider 矩阵只证明确定性、效果隔离和故障隔离，行为保持 `partial`。

CDR-042 没有足够公开事实可以确定商业版 Spring 的完整接触规则、时间和发射数值。四方向效果和生命周期基于已验证的固定 tick 与通用运动合同独立设计。程序生成的 Player/Theo/Glider/双 Spring 矩阵只证明确定性路由和隔离，行为保持 `partial`。
