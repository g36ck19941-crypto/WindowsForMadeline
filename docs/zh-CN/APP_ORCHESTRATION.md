# 离线 App 统一编排

CDR-050 新增 `CelesteDesktop.App`，把此前验证过的离线模块放进同一个运行会话。它只负责“什么时候启动、每一步先做什么、效果交给谁、失败后关掉哪一块”，不把玩法规则重新写进 App。

## 每个时间点怎么运行

一个 App tick 只让模拟世界前进一步，固定为 60 Hz。顺序是：

1. Spring、Refill、Water、Bumper、Puffer、Seeker 按固定顺序计算；
2. 把带目标身份的速度或资源效果交给 Player、Theo 或 Glider；
3. 更新 Theo、Glider，最后更新 Player；
4. 保存不可变快照；
5. 模拟完成后才把动画帧交给呈现层。

同一轴收到多个速度时采用“第一个生效”，并记录 `APP_EFFECT_CONFLICT`，不会悄悄覆盖。找不到目标会记录 `APP_EFFECT_TARGET_UNRESOLVED`。Seeker 命中仍只是命中事实，App 不会擅自把它解释成 Player 死亡。

## 生命周期和故障隔离

状态顺序是“已创建 -> 运行中 <-> 已暂停 -> 已停止 -> 已释放”。错误顺序会明确报错。呈现层或单个可选实体失败时，只禁用出错组件，保存完整异常，其他模拟继续。Player 或核心模拟失败才会让整个会话进入故障状态。

## 它在项目中的作用

简单说，以前各模块像一组已经单独测试过的零件；CDR-050 增加了“总调度员”，保证每个时间点只推进一次、按同一顺序传递效果，并且显示部分坏掉时角色模拟不会一起停。这是以后连接真实应用宿主的必要基础。

本任务仍不能证明原版素材已显示、手感完全一致、真实键盘可用或桌面上人眼可见。本次没有 GUI、实时输入、游戏安装访问或商业素材。
