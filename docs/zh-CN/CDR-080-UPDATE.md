# 原版逻辑本地重组方案
更新：2026-10-03；英文规范见 ../ORIGINAL_RECOMPOSITION.md。

## 现在到了哪一步
旧的自主角色、八种实体、碰撞运动核和玩法编排已删除，相关测试和演示一起退役。移除了 24 个项目；Git 历史和本地恢复分支还在，不是永久销毁历史。
保留工具链 Release 构建无警告、无错误，12 组共 298 项测试通过。现在没有可以运行的角色。

本机反编译缓存有 1369 个 C# 文件；目录清点发现 256 个文件位于包含 Celeste.Mod/Everest/MonoModRules 标记的路径。
因此它不是已经确认的“纯原版缓存”。我们尚未确定每处补丁的来源和影响，不能直接拼起来就宣布还原成功。
此前 CDR-016 验证的 93 个动画、706 帧是资源解析的历史证据，不是反编译生成的图片，更不是角色运行证据。

## 怎样完成重组
1. **先认清拿到的是什么（CDR-081）**：确认版本、哈希、原版还是 Everest，再列出角色真正需要的引擎、状态机、时钟、输入、碰撞、动画等依赖。只拿到 Player.cs 并不意味着能运行 Player。
2. **先拼一个最小可编译核心（CDR-082）**：在 Git 忽略的本地目录中恢复角色及必要的原版引擎依赖，保留原来的行为顺序和规则，不再写另一套近似玩法。先做角色和最小环境，不一次拼全游戏。反编译代码可能需要处理编译器还原和依赖兼容问题。编译成功也不代表运行正确。
3. **接上正版资源并离线验证（CDR-083）**：原版逻辑要求什么资源名，就由现有读取工具从本地资源中找到对应动画和帧。再用人工生成输入逐步更新，检查状态、碰撞和离屏画面。图片不是从反编译代码里凭空产生的；缺少依赖要明确报错，不能偷偷用自定规则补上。
4. **换成桌面环境（CDR-084）**：我们仍需写一层薄的连接代码，提供时间、输入、资源、画面输出和桌面几何；行为核心尽量沿用恢复的原版逻辑。即使不要关卡，原版角色也可能依赖最小场景和会话环境。先证明角色，再逐个接入实体。
5. **最后验证真的看得到、能动**：离线结果成立后，再单独授权桌面窗口与真实输入测试。不能拿“有帧”“提交成功”代替你真的看见角色。

## 哪些东西不会上传
反编译源码、IL、原版程序集、商业图片、音频、地图及含商业代码的构建产物只留在本地忽略目录。GitHub 只保存我们自己的工具、适配代码、合成测试和摘要记录。
本地保存不等于取得任意使用或传播权利，也不能把商业代码当 MIT 开源代码发布。
不会启动完整 Celeste/Everest；也不会直接加载整个游戏 DLL 来碰运气，初始化可能触发游戏系统。

## 它在项目中的作用
这次清理撤掉了与原版竞争的另一套玩法，让后续工作的依据转向原版代码。保留工具负责“把资源读对、把画面送出去”，但尚未把原版角色拼成可运行核心。
重组是否可行要靠来源确认、依赖清点和最小编译验证，当前不能保证百分百还原。

## 具体验收方式
双击根目录“演示当前进度.cmd”，应看到清理、缓存和缺少功能的中文说明，不再看到旧角色演示。
双击“验证当前版本.cmd”，预期最后显示 CDR080_VERIFIED suites=12 passed=298。
验证不会启动游戏、可见 GUI或访问安装目录；演示入口只有你主动双击时才打开状态页面。
验收后建议开始 CDR-081：确认源程序集身份、梳理原版依赖，不再继续自主玩法校准。
