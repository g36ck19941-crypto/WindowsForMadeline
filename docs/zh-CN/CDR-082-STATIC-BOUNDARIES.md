# CDR-082：编译之后，还差哪些运行条件

2026-10-03，Primary。本次只阅读已经恢复的本地源码；没有重新访问安装、运行原版代码或打开窗口。不是CDR-083已经实现。

## 它在项目中的作用

编译通过相当于零件能拼成一个库。现在检查的是：真正创建角色前，哪些配套设施必须准备好，哪些会触碰禁止的窗口、输入、声音和Steam。这样可以避免下一步直接启动整套游戏引擎。

## 看到了什么

- 创建角色时已经需要精灵目录、头发纹理及输入状态，并非只用坐标就能生成角色。
- 把角色放进场景时，它会寻找原版关卡环境并使用边界；随便创建一个空场景不能证明可行。
- 角色更新依赖时间、输入、辅助设置、音频和场景。需要控制这些外围设施，同时保留原版运动和碰撞规则。
- 原引擎构造会配置绘图设备和窗口；游戏启动/更新包含Steam调用路径，音频初始化包含原生FMOD调用。不能把普通启动流程当作“不打开窗口”的办法。

这是源码中的静态依赖观察，不是所有路径都一定执行的证明，也不是完整调用链或运行安全保证。没有改商业源码，没有实现替身玩法。

## 下一步顺序

先明确角色构造和更新的调用边界，再设计我们自己的外围适配；若需要本地改造原版源码，须先说明并确认。真正运行恢复代码、读取角色资源或创建离屏绘图设备前，另行限定授权范围；不默认允许游戏入口、Steam、真实输入或窗口。
