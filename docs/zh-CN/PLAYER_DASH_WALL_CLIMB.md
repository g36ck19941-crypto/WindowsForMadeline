# CDR-022 冲刺、墙面与攀爬

## 实现内容

`PlayerTraversalController` 把程序生成的逐 tick 输入接到 CDR-021 普通移动/跳跃控制器上，新增明确的 `Normal`、`Dash`、`WallSlide`、`Climb` 状态。它不读取实时输入，也不依赖时钟、GUI、文件系统或操作系统。

当前实现包含八方向数字输入量化、冲刺次数/冷却/补充/攻击窗口、9 tick 冲刺和结束速度、碰撞事件、墙体距离检查、墙滑/蹬墙、抓墙/松手、攀爬速度、体力消耗与疲劳/耗尽、攀爬跳、越过合成边缘，以及隔离的无限冲刺/无限体力辅助。每个 tick 都输出不可变快照。

本任务还通过新轨迹发现并修复了一个模拟核心缺陷：亚像素余量恰好为 `+0.5` 或 `-0.5` 时，后续零位移不再让位置来回抖动；正负两个方向都有独立回归测试。

公开参数和大体顺序依据 Celeste 官方公开 `Player.cs` 中可确认的事实重新设计：<https://github.com/NoelFB/Celeste/blob/master/Source/Player/Player.cs>。没有复制实现文本。完整发行版周边条件仍无法由公开资料证明，因此状态保持 `partial`。

## 具体验收方式

1. 双击 `演示当前进度.cmd`。
2. 查看 CDR-022 的 24 tick 表格，确认能看到 `WallSlideStarted`、`WallJumped`、`DashStarted`、`DashBlocked` 和 `ClimbStarted`。
3. 确认攀爬速度最后达到 `-45`、体力从 110 下降；速度为 0 的冲刺/抓墙行不应发生位置来回抖动；重复运行标为“完全一致”。
4. 双击 `验证当前版本.cmd`。十组共 298 项离线测试应全部通过，最后一组为 `44/44`，随后 CDR-022 演示清单核验通过。
5. 全过程不读取真实安装，不启动游戏、GUI 或真实桌面，也不读取实时输入。

## 它在项目中的作用

简单说，这一步把第一套离线角色移动能力补齐了：角色逻辑现在能在同一个确定性状态机中跑、跳、冲刺、贴墙、蹬墙、攀爬并消耗体力。以后 Theo、水母、弹簧等物品可以根据明确的玩家状态和事件交互，而不是靠猜坐标。

它还没有实现上冲转角修正、单向平台、移动墙提升、攀爬阻挡器、所有辅助选项、下蹲/超级技巧、搬运、水和环境变体，也没有接入实时控制、角色素材、渲染或桌面，因此不能证明完整发行版手感或角色已经可见。
