# Atlas Metadata Reader

## Implemented function

CDR-012 adds an independent, synchronous `.meta` reader that converts one bounded stream into immutable atlas, page and entry descriptors. It does not open paths itself and has no filesystem, Worker IPC, image decode or rendering behavior.

The supported structural facts are:

1. signed 32-bit format version;
2. .NET 7-bit-length-prefixed UTF-8 packer name;
3. signed 32-bit packer version;
4. signed 16-bit page count;
5. for each page: one bounded logical data path and signed 16-bit entry count;
6. for each entry: one bounded logical ID followed by eight signed 16-bit values for atlas rectangle, stored trim offset and untrimmed frame size.

Format facts were checked against the public [Crunch binary-format description](https://github.com/ChevyRay/crunch#binary-format) and the independently published [desk-madeline format observation](https://github.com/solstice23/desk-madeline/blob/master/CelesteAtlas.cs). This repository does not copy either implementation. Real-install compatibility remains unverified until CDR-016.

## Role in the project

CDR-012 teaches the project how to understand the atlas index: which logical sprite ID belongs to which page, which rectangle contains it, and where a trimmed image belongs inside its original frame. This is the table of contents needed before page pixels can be decoded.

It still cannot decode `.data` pixels, find Madeline animations, display a character or prove compatibility with the user's installation.

## Safety boundaries

- default total consumed input: at most 16 MiB;
- string payload: at most 1,024 UTF-8 bytes;
- pages: at most 64;
- total entries: at most 100,000;
- entries per page: at most 32,767;
- coordinates, dimensions and frame extent: at most 16,384;
- strict UTF-8 and canonical 7-bit string lengths;
- slash normalization plus Unicode Form C normalization;
- absolute, rooted, drive-qualified, empty-segment and traversal paths rejected;
- page paths and entry IDs unique with ordinal case-insensitive comparison;
- negative coordinates, empty dimensions, extent overflow, impossible trim and `Int16.MinValue` negation rejected;
- truncation and all trailing bytes rejected;
- no partial descriptor is returned after any failure.

Stable failures use the owning `ATLAS_META_*` family.

## Verification

Run from the repository root:

```powershell
.\tools\Verify-CDR012.ps1
```

Expected results:

- Release build: 0 warnings, 0 errors;
- CDR-010 regression: `RESULT total=15 passed=15 failed=0`;
- CDR-011 regression: `RESULT total=27 passed=27 failed=0`;
- CDR-012: `RESULT total=32 passed=32 failed=0`.

The CDR-012 suite uses generated bytes only. No `.meta` file, commercial asset, game installation, game process or GUI is used.

## Current limitation

This is synthetic format verification, not `asset_exact`. The reader is not yet exposed through Worker IPC, no real `Gameplay.meta` has been read, and no `.data` page can be decoded.

## Next gate

Developer acceptance authorizes only CDR-013: a bounded `.data` RLE decoder using generated pixel runs and exact synthetic BGRA32 expectations. Real installation access remains separately gated at CDR-016.
